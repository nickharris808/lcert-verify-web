# Contributing

## The rules

1. **No dependencies, no build step.** `src/lcert.js` must stay loadable directly by a browser
   from a `file://` URL. A verifier that needs a toolchain is a verifier nobody runs.
2. **Never widen a tolerance to make a test pass.** If the JS and Python implementations disagree,
   the JS is wrong until proven otherwise. The conformance suite compares against fixtures
   generated by Python; regenerate them with `npm run fixtures`, never hand-edit them.
3. **Bit-identity is a claim, so test it.** Any change to the interval arithmetic must keep the
   per-locus classification exactly equal to the reference. Add fixture cases in the same commit.
4. **Document divergences in the README.** Two are documented today (erfc approximation, canonical
   JSON). If you add a third, it goes in the README with a measured bound, not a hand-wave.

## Running the suite

```
npm run fixtures    # needs python3 and the sibling lcert-verify package
npm test
```

## Reporting a soundness bug

A bundle that shows VERIFIED in the browser but fails the Python verifier (or vice versa) is the
most serious bug class here. Include the bundle and both outputs.
